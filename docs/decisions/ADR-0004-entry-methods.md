# ADR-0004: Методы нахождения точек входа (анализ внешних мнений)

Дата: 2026-08-27
Статус: Принято (частично; отложенные элементы зафиксированы)
Контекст: анализ предложений ChatGPT / Claude / Gemini / DeepSeek +
описание текущего пайплайна (Темотрон), сквозь призму собственных
эмпирических результатов исследовательской программы QuantAI
(~100+ конфигураций входа, 3 года данных, единый WF-жгут).

## Контекст измерений (решающий аргумент)

1. Single-asset directional входы (confidence-stack, breakout,
   MTF-gate, meta-labeling, regime-gate) — **нет OOS-эджа после
   издержек** ни в одной конфигурации на 1h/4h.
2. Причина смерти подтверждена численно: издержки ≈0.10–0.14%/круг
   против валового ожидания ≈0.05%/сделку + частота.
3. Найден живой эдж **вне тайминга**: кросс-секционный momentum
   (weekly rebalance, топ-K из 18 альтов) — PF_med 1.43 OOS,
   первый чемпион банка (`xs_lb7_k2`).
4. Временные риск-оверлеи (dd-gate/vol-target) режут хвостовые
   прибыльные окна быстрее медиан → контур отказал в промоушене
   (правила не согнуты).

## Решение

### Принимается (контракт будущего Entry Engine — только как КАНДИДАТЫ через банк)

| Элемент | Источник | Обоснование |
|---|---|---|
| EV-гейт с ЯВНЫМИ издержками | ChatGPT §8 | Прямое лечение доказанной причины смерти: `EV = p·TP − (1−p)·SL − round_trip_costs > threshold` |
| Setup ≠ Trigger (стейт-машина) | ChatGPT §4 | Разделение «ситуация зреет» / «момент настал»; состояния NO_SETUP→WAIT_TRIGGER→WAIT_CONFIRMATION→EV_TOO_LOW/RISK_BLOCKED→ENTRY_APPROVED |
| Entry TTL | ChatGPT §10 | Запрет устаревших сетапов; встраивается в pending-механизм TradeEngine |
| Entry Zone + лимитник (maker) | ChatGPT §9 + DeepSeek (retest) | Комиссия 0.02% vs 0.05% — второй удар по killer'у издержек |
| Независимость подтверждений | ChatGPT §5 | Факторные группы вместо голосования дублирующих индикаторов |

### Отклоняется / откладывается

| Элемент | Причина отклонения |
|---|---|
| Мультипликативный EntryQuality без WF-калибровки весов | Псевдоточность (прецедент: WeightedGate 0.6/0.4 без селективной силы) |
| Полный 7-слойный Entry Engine «сейчас» для directional-трека | Эмпирически: под слоями нет edge для усиления; частота/издержки — биндер |
| L2/Order Flow подтверждения, POI/FVG (Gemini) | Нет исторической L2-инфраструктуры; OFGate сегодня получает None. Отложить до data-infra этапа |
| Дискреционные паттерны (pin-bar, MSB, Fib) как ручные правила | Неформализуемы робастно; классические TA-семьи OOS-эджа не показали. Только как кандидаты через банк |
| BMAD-терминология | Бэкроним поверх Wyckoff/ADX-классики (см. обсуждение); используем RegimeFilter |

### Уже реализовано (совпадения с мнениями)

- Regime-first: `RegimeFilter` Stage A + AIAnalyzer режимы
- Flat Timeout: `ExitPolicy.time_exit_bars`
- Maker-first: моделируется издержками; лимитное исполнение — в bridge
- Candidate→Champion для любых entry-методов: R4-pipeline работает (P-C1 — живое доказательство)
- Мульти-ТФ фильтр: `MTFConfirm` построен, измерен (≈0 эффекта), выключен

## Последствия

1. Directional entry-развитие замораживается до появления телеметрии
   от Long-Run чемпиона; любые новые entry-стратегии входят ТОЛЬКО
   как кандидаты (WF → правила → турнир → сравнение с чемпионом).
2. Первый приоритет прибыли остаётся у портфельного класса
   (частота ↓, издержки амортизируются шириной кросс-секции).
3. Введение Entry Engine начнётся с EV-гейта и стейт-машины —
   элементы, чья ценность не зависит от наличия эджа у сигнала.
