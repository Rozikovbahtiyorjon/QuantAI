# Роль

В новой структуре появился `src/risk/risk_orchestrator.py` вместе с `cross_margin.py`, `dynamic_risk_budget.py`, `kelly_sizer.py`, `portfolio_correlation.py` — это новый, более узкий risk-подкластер. Одновременно в `src/` (плоско) остаются старые 13 risk-файлов из прошлого аудита. Нужно понять реальную картину заново, не полагаясь на прошлый вывод («risk-кластер не подключён») — она могла измениться.

# Известная задача №1

1. Прочитать `risk_orchestrator.py` полностью: какие из старых risk-модулей он импортирует напрямую, какие функции/классы оттуда вызывает.
2. Составить таблицу: старый risk-модуль → используется ли в `risk_orchestrator` (да/нет) → используется ли где-то ещё в проекте (paper_trading_runner, trade_engine, strategy).
3. Для модулей, которые НЕ используются нигде — явно предложить решение: подключить в `risk_orchestrator` (если функционально не дублирует то, что уже там есть) или зафиксировать как «архивировать» (не удалять самостоятельно — только рекомендация, решение по архивации принимает пользователь).
4. Обязательно проверить дублирование: не получилось ли так, что `risk_orchestrator` + `kelly_sizer`/`dynamic_risk_budget` теперь параллельно делают то же, что старый `position_sizer.py`/`capital_allocator.py` — это тот самый паттерн дублирования ответственности, который уже был найден в прошлом аудите.

# Жёсткие правила проекта

- **Rule 2 (Do Not Rewrite Working Modules)**: если старый модуль уже используется где-то стабильно (например `risk_manager.calculate_sl_tp` в `strategy.py`) — не трогай эту связь, даже если кажется, что `risk_orchestrator` должен её заменить. Замена — отдельное решение пользователя, не твоя инициатива.
- **Rule 3-5-7** (из системного контекста): при любой доработке risk-логики — не выходить за рамки: максимум 3% риска на сделку, максимум 5% суммарной экспозиции, профитные сделки должны давать в среднем на 7%+ больше убыточных. Если видишь, что новый или старый модуль нарушает это — фиксировать явно, не молчать.

# Формат сдачи

Таблица использования (см. п.2) + отдельный список найденных дублирований ответственности между новым и старым risk-кластером, с конкретными именами классов/методов.

# Границы

Не удаляй и не объединяй файлы самостоятельно — только диагностика и рекомендация. Решение о слиянии/архивации — за пользователем.
